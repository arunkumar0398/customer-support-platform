## Trusted source binding

The host launcher requires an explicit 40-character commit that equals HEAD in a clean worktree. It uses trusted Git commands to inspect the complete recursive tree and create git archive; dirty source is refused. Tracked secret/credential/cache/output paths, symlinks, gitlinks, and unsafe path components are refused. The only environment-file exception is the exact root `.env.example`: the launcher parses it as bounded text and accepts only the reviewed variable set, exact non-secret local settings, fixed placeholder secret values, and loopback PostgreSQL URLs. A real `.env`, nested template, duplicate/unknown assignment, changed credential value, or non-local database URL is rejected. Ignored/untracked host files are excluded because the archive is created from the selected commit, not the working directory.

The launcher records the commit and tree IDs, object format, recursive tree path/mode/blob manifest and digest, Git archive commit marker, archive SHA-256/size, pinned image/lock/schema/manifest digests, launcher and runner hashes, and safe execution settings. The Linux verifier checks the Git archive marker and compares every archive regular-file path, blob object ID, mode, and count with the selected Git tree manifest. An archive with a copied commit marker but altered content is rejected. Input archives and records are read-only to target code.

Run only after all intended source and documentation changes are committed:

    $repo = (Resolve-Path .).Path
    $sha = & 'C:\Program Files\Git\cmd\git.exe' -C $repo rev-parse HEAD
    & node audit/host/launch-offline.mjs --execute --repo $repo --commit $sha --lane api --evidence-dir C:\Users\sivaa\security-audit-skill\customer-support-platform\run-20 --timeout 5400

Use a new empty evidence root per run; the launcher creates a unique child directory. It refuses a dirty/non-HEAD source, a non-local Docker engine, non-Linux/non-AMD64 server, unexpected image digest, existing output collision, or unsupported lane. The record contains the sanitized host Docker context/server, host OS/architecture, actual target/helper argument arrays (with only the self-referential launch-record hash represented by an explicit placeholder), mounts, UID/capabilities, environment allowlist, resource ceilings, timeout, volume/container names, and helper limits. Do not put credentials or database URLs in the evidence record.

## Isolation and artifact promotion

The target has one bounded container-private tmpfs at `/scratch`; no helper mounts that tmpfs, so Docker local-volume remount behavior cannot change its ownership or erase target output. A separate bounded preflight container checks the exact pinned image, source binding, mount modes, network routes/interfaces, proxy absence, versions, UID, cgroups, swap, PID/file/disk limits, safe dummy DB URLs, and source/toolchain hashes before the API container starts. The fixed target runs with `--pull=never --network=none --read-only --user 10001:10001 --cap-drop=ALL --security-opt=no-new-privileges`, 1 CPU, 1536 MiB memory, zero swap, 256 PIDs, 1 GiB file-size limit, 1.1 GiB scratch and a maximum 90-minute timeout. Only the committed source archive and runner copies are mounted read-only; target has no artifact mount, Docker socket, parent promotion directory, host home, or cache. Only explicit allowlisted environment variables are supplied.

The trusted Linux promoter starts before the API target and opens directory descriptors for a separate, empty, parent-created promotion-input directory and the artifact volume. Its input directory is mounted read-only to the promoter and is never mounted into the target. After the target container has exited and its stopped state is verified, the parent captures stdout/stderr with byte limits, redacts common credential/URL/email patterns, and writes only the fixed allowlist `preflight.out`, `lane.log`, and `lane-result.json` with exclusive creation, regular-file/single-link/size checks. The promoter then reads those files through descriptor-relative no-follow opens, rejects traversal/special files/symlinks/hard links, verifies identity before/after bounded reads, detects changes and growth, writes a fresh private staging directory and atomically renames it. The promoter keeps its artifact mount alive until the parent copies each exact file and checks the Linux promotion hash; a matching run-ID acknowledgement then lets the helper exit. The parent never recursively copies target scratch. On uncertainty, it keeps the exact artifact volume and private host input/staging directories and records their identities in `RECOVERY.txt`; reconcile those exact objects before retrying. After verified promotion and hashes are recorded, success cleanup removes only the exact mkdtemp-created directories after resolving them beneath the OS temp root and refusing symlinks. Failed cleanup leaves a marker in the external run directory. The target cannot access the artifact volume, promotion input, or Docker socket.

Host output is retained under the external evidence root, not in the source tree. Sanitize before sharing. Do not promote screenshots, credentials, environment files, browser profiles, arbitrary logs, or unallowlisted files. The helper's unit tests cover symlink, hard-link, FIFO/directory/socket, traversal, oversized and changing files, duplicate/overwrite refusal, and file-set bounds; source-verifier tests cover forged archive payloads with a claimed commit marker and launch-configuration tampering.

The API lane runs disposable PostgreSQL migrations and npm run test:api; Web runs the Web suite; browser runs the local synthetic browser suite; all additionally runs lint, typecheck, build, and browser discovery/execution.
