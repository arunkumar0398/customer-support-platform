# Multi-Tenant Customer Support — Codex Desktop Starter Kit

**Status: HANDOFF ONLY.** This repository initially contains assessment requirements, agent rules, plans and validators. It does **not** contain the application, passing tests, configured cloud resources, a GitHub remote or a deployed website. Codex Desktop is expected to build these in ordered, verifiable checkpoints.

The downloaded ZIP is **root-ready**: unzip its contents directly into an empty folder named `customer-support-platform`. Do **not** keep a nested `support_assessment_harness_plan/` directory. The PDF must be at `reference/assessment.pdf` and the agent policy must be at root `AGENTS.md`.

## 1. Prepare on Windows (PowerShell)

Install prerequisites: Git, Node.js LTS appropriate to the pinned project dependencies, npm, Docker Desktop (with Linux containers/Compose), Python 3, and Codex Desktop. Docker Desktop must be running when executing integration tests.

Create an **empty** directory and extract this ZIP **into that directory** using Windows Explorer or `Expand-Archive`. For example, from the folder holding the downloaded ZIP:

```powershell
New-Item -ItemType Directory -Force -Path .\customer-support-platform | Out-Null
Expand-Archive -LiteralPath .\customer_support_codex_desktop_starter_kit.zip -DestinationPath .\customer-support-platform
Set-Location .\customer-support-platform
py -3 .\scripts\verify_kit.py
powershell -ExecutionPolicy Bypass -File .\scripts\doctor.ps1
if (-not (Test-Path .git)) { git init -b main }
git status --short
```

If a file conflict exists, **stop** and inspect it instead of force-extracting over local work. You can also unzip manually; the ZIP filename is not important.

Make the initial scaffold snapshot only after inspecting the extracted files:

```powershell
git add .
git diff --cached --stat
git commit -m "chore: add assessment contract and Codex Desktop harness"
```

Git user identity may need configuration first. Do **not** add `.env`, passwords, `.vercel`, database files, build outputs or real customer data. Private GitHub remote is optional until you choose to publish; **do not push as part of this bootstrap**.

## 2. Enable official Superpowers skills in Codex Desktop

The preferred installation is **Codex Desktop → Plugins → Coding → Superpowers → +**, followed by app restart if prompted. Official project: https://github.com/obra/superpowers . The plugin is installed in the **agent environment**, not vendored into this repo. Ask Codex to prove skill discovery rather than assuming it worked. If you use Codex CLI instead, its `/plugins` command has its own installation route.

Required skills where available: `using-superpowers`, `brainstorming`, `writing-plans`, `using-git-worktrees`, `test-driven-development`, `systematic-debugging`, `verification-before-completion`, `requesting-code-review`, `receiving-code-review`, and `finishing-a-development-branch`. `subagent-driven-development` and `dispatching-parallel-agents` require supported multi-agent functionality; use a serialized review workflow if unavailable.

## 3. Open this folder in Codex Desktop

1. Open **this folder** as the workspace.
2. Choose a local agent task, not Codex Cloud.
3. Read `prompts/MASTER_CODEX_DESKTOP_PROMPT.md` and paste its **entire** `BEGIN MASTER PROMPT` section into Codex.
4. Expect the first output to confirm path, Git state, availability of skills, PDF requirements, unresolved assumptions, and design/plan. Let it implement the initial safe **local** tasks once the design gate is approved.
5. Use `prompts/NEXT_CHECKPOINT_PROMPT.md` for successive bounded checkpoints and `prompts/RESTART_PROMPT.md` after context resets.
6. Use `prompts/INDEPENDENT_REVIEW_PROMPT.md` before deployment and at the final release SHA.
7. Deployment is a separate **human-authorized** step; use `prompts/DEPLOYMENT_PROMPT.md` and `harness/VERCEL_NEON_DEPLOYMENT.md` only after all local MVP gates pass.

## 4. Design locked unless evidence forces a change

- React + Vite + TypeScript, Node + Express + TypeScript, Prisma + PostgreSQL, Zod, TanStack Query, Tailwind.
- npm workspaces with `web/` and `api/` (created by Codex).
- Local: Docker Compose PostgreSQL, real test database, repeatable migrations and two-tenant seeds.
- Deployed: **Vercel** static Vite frontend and **Vercel** Express Node.js Function as two projects from the same GitHub repository; **Neon PostgreSQL** for preview/production.
- Browser same-origin `/api` proxy through Vercel rewrite; tenant isolation on server; pooled Neon runtime connection and direct migration connection.
- Deploy after secure, reproducible MVP. Assessment deployment is optional; if deployment cannot be proven, submit the secure local slice without claiming it is live.

## 6. Progress discipline

Every task ends with branch/SHA, changed files, failing-test proof, passing-test proof, exact commands and exit codes, assessment IDs, review findings and next action. Results go into `evidence/checkpoints/`; no imagined or fabricated evidence. All app tests are **NOT RUN** when this kit is first installed.

**Two tracks:** deliver the PDF-required secure local vertical slice within the suggested 2–3 day effort (document overruns), then optionally complete Vercel + Neon deployment and extensive independent review. Do not sacrifice isolation/security to hit an optional deployment goal.
