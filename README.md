# Multi-Tenant Customer Support Platform

**Status (2026-10-27):** implementation is in progress. The repository has TypeScript workspaces, local PostgreSQL, a Prisma domain schema, a synthetic two-organization seed, safe API errors, password/session authentication, tenant-scoped membership administration, ticket creation/list/detail/update/assignment/comment/history APIs, and tenant-scoped dashboard metrics. The React sign-in and authenticated shell are implemented. The ticket queue now supports tenant-scoped search, status/priority/assignment filters, customer-owned ticket visibility, URL-backed pagination, and loading/empty/error states; these journeys are browser-tested against the real API and disposable PostgreSQL fixtures. Ticket creation/detail/dashboard/admin screens and full Docker app launch remain pending. No hosted deployment is configured or claimed.

The employer assessment PDF is the product contract in [`reference/assessment.pdf`](reference/assessment.pdf). The approved design, task plan, acceptance matrix, security contract, and assumptions are under `docs/` and `harness/`.

## Local database setup

Use Node 24, npm 11, Git, and Docker Desktop with Compose. On PowerShell, copy `.env.example` to `.env` if needed and replace its local placeholder values with random local-only values. Do not commit `.env`.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm ci
docker compose up -d database
npm run db:wait
npm run db:migrate
npm run db:seed
```

The seed command verifies a loopback `support_dev` connection before writing. It creates synthetic records only. Database integration tests use the separate disposable `support_test` identity; run `npm run db:migrate:test` and `npm run db:verify-test` to check that target.
