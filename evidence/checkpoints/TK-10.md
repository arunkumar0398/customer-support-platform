## Changes and contract clarification

- `api/src/lib/policy.ts` centralizes admin-only membership administration, staff capabilities, organization/customer ticket visibility, own-OPEN-only customer content edits, non-closed comments, and staff-only status/priority/assignment authority. Inaccessible/absent tickets return the same 404 before action-specific state is disclosed.
- `ticketScope` combines mandatory organization/customer ownership with other Prisma criteria using AND. Incomplete server context and unrecognized roles fail closed rather than yielding an unscoped query. This query-object contract is unit-tested, not claimed as executed SQL or an implemented product route.
- `api/tests/auth/policy.test.ts` contains 35 unit cases over the policy matrix, foreign/other-customer negatives, states, and mandatory query scope.
- ADR 0003 clarifies an ambiguous combined comment/history row in the approved design. The original PDF page 1 requires conversation and meaningful change history and lets us define business rules; it does not require hiding closed history. The harness default restricted new comments on closed tickets. The design now splits adding comments from reading history: authorized closed history stays readable, while new closed-ticket comments remain denied. Organization/customer boundaries are unchanged. `docs/api.md` documents this policy foundation and its integration limits.
