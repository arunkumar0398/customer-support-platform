## Contract and changes

- Ticket detail returns a strong quoted version ETag. Ticket content updates and assignment updates both require a matching `If-Match` ETag.
- Missing preconditions return 428 `PRECONDITION_REQUIRED`; malformed/weak/multiple/out-of-range ETags return 422; stale versions return 409 `VERSION_CONFLICT` without mutation.
- Services revalidate the current membership and authorize/scoped-load the ticket inside the organization-locked transaction, then compare versions before no-op returns or writes. A stale request cannot silently succeed even when its requested value matches the current value.
- Successful writes return their current ETag. Ticket and event writes remain in the same transaction.
- Assignment concurrency was added after both reviewers found that the original TK-20 change protected content updates but left assignment writes unversioned. A real PostgreSQL regression first reproduced two concurrent successful assignments from the same version.
- `docs/api.md` now documents the shared version-precondition contract for both mutation routes.
