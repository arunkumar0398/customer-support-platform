## Contract and changes

- Added `PATCH /api/tickets/{ticketId}/assignment`, requiring current ADMIN/AGENT authority and an active same-organization AGENT target. `{ assigneeUserId: null }` clears the assignment.
- The service locks the organization row, reloads current active actor membership, and selects the ticket through its mandatory tenant scope. Missing/ineligible targets and inaccessible tickets return a generic 404. Customer actors receive 403.
- Assignment uses both organization/user relation keys; a PostgreSQL composite-FK negative verifies cross-organization assignment is blocked even outside the API. Changed assignments increment version and record `ASSIGNMENT_CHANGED` in the same transaction; repeated assignments are no-ops.
- Strict input rejects malformed IDs and additional fields. API docs and README describe the route and eligibility rule.
