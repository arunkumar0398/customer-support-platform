## Contract and changes

- Added `GET /api/tickets/{ticketId}` behind existing session authentication and server-derived active organization middleware.
- UUID path values are validated and normalized. The database lookup includes `ticketScope(actor, { id })` in the `WHERE` clause, so organization and customer ownership constraints are applied before the record is returned.
- Missing, cross-organization, and same-organization other-customer records return the same generic 404 response. Authorized staff see organization tickets; customers see their own. Responses are `no-store` and contain the ticket DTO, not credentials, comments, or activity history.
- Updated API docs and README to reflect detail-route availability and its remaining boundaries.
