## Contract and changes

- Added authenticated `POST /api/tickets`; middleware derives organization/current role, service locks the organization row, re-reads current active membership, then validates/acts on the current role.
- CUSTOMER strict input allows only trimmed title/description; requester is derived from actor, priority MEDIUM, status OPEN, assignee null, dueAt null, version 1.
- ADMIN/AGENT strict input also requires requesterUserId and accepts optional priority. Requester must be an active CUSTOMER membership in the selected org. Inactive, staff, missing, and foreign requesters return a generic 404. Customer-supplied requester, status, priority, organization, assignee, number, version, timestamp, or event properties are rejected.
- Ticket numbers use organization-scoped max+1 inside the same org row lock shared with membership writes. This handles parallel API creation; DB uniqueness is the final guard. Integer ceiling returns 409. Repeated requests create distinct tickets; no idempotency is claimed.
- Prisma nested create persists one `TICKET_CREATED` event with the ticket. Database-trigger fault injection against a uniquely named function/trigger constrained to this disposable fixture org proves the event failure rolls back the ticket and number. Trigger/function dropped in `finally`; recovery create starts at 1.
- API/README documentation updated. No schema, migration, dependency or lockfile changes.
