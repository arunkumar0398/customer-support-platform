## Changes

- Added `api/prisma/seed.ts` with deterministic IDs, organization-scoped ticket numbers 1–4 in Alpha and Beta, eight demo accounts (one admin, one agent, and two customers per organization), and eight ticket fixtures spanning all statuses/priorities, assigned/unassigned records, two customer owners per organization, and overdue active tickets.
- Seed writes run in one PostgreSQL transaction and use deterministic upserts. The CLI entry point accepts only a loopback `support_dev` URL and verifies the database-reported role/database before writing. Importing the seed module does not run the CLI.
- Stored per-account scrypt hashes use distinct salts (`N=32768`, `r=8`, `p=1`). The shared synthetic password is documented in `docs/demo-accounts.md`; the integration test derives each hash from that documentation and verifies it with Node's scrypt implementation.
- Added `api/tests/db/seed.test.ts` to verify test-database identity, organizations and roles, hash/password consistency, tenant/customer/lifecycle/priority/overdue fixtures, and idempotency across repeated calls.
- Updated the API seed command to invoke the guarded local CLI. Replaced the starter-kit README's now-stale empty-repository instructions with the current project state, local database setup, seed/test commands, and explicit note that sign-in is not implemented.
