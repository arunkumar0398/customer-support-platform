## Contract and changes

- `GET /api/tickets` accepts optional one-based `page` (1–1000, default 1) and `pageSize` (1–100, default 25). Numeric values must be decimal integer query strings; repeated parameters, unknown keys, malformed values, and out-of-range values return 422.
- The service applies filters and mandatory tenant/customer policy before paging, with scoped `total` and items read in one PostgreSQL RepeatableRead transaction.
- Pages use `createdAt DESC, id DESC` to stabilize ties, then `skip=(page-1)*pageSize` and `take=pageSize`. The response is `{ items, total, page, pageSize }`.
- API documentation now describes the full pagination contract. No UI journey or full G3 claim is made.
