### Root cause and regression fix

A first clean-worktree startup at `4e28dbbd0838993637a4e0f12d26c885dfec1abe` failed with PostgreSQL container exit 127. Its log showed `env: can't execute 'bash\r'`: Windows Git had checked out the mounted init script with a CRLF shebang, so `/usr/bin/env` looked for `bash\r`. The committed blob was LF, but no repository attribute constrained checkout line endings. Added `.gitattributes` with `docker/postgres/*.sh text eol=lf`. A brand-new worktree at the fix commit reports `i/lf w/lf attr/text eol=lf`; its first shebang line contains no CR byte.
