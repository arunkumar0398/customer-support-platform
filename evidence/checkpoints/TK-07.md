## Changes

- `api/src/app.ts`: server request ID before JSON parsing; 32 KiB uncompressed JSON limit; terminal not-found and error middleware.
- `api/src/middleware/request-id.ts`: a fresh UUID per request, ignoring caller-supplied IDs; correlation header on success and error responses.
- `api/src/middleware/errors.ts`: consistent safe JSON for 400/404/413/415/422 and unexpected 500 responses; expected application 4xx errors share the envelope. No raw error, stack, request body, header, cookie, URL, or database message is logged. Unexpected errors log only correlation metadata. A response that already started is closed without delegating its raw error to Express's default logger.
- `api/src/middleware/validate.ts`: Zod object body validation enforces strict top-level allowlists, rejects invalid/unknown fields with 422, and passes parsed/normalized data onward. Nested schemas remain responsible for their own strictness.
- `api/tests/http/errors.test.ts`: 19 real HTTP checks through Supertest; production-app requests plus test-only Express routes using the production middleware. No product-only test endpoints were added. This is HTTP integration evidence, not PostgreSQL/auth/browser verification.
- `docs/api.md`: current endpoint, envelope, statuses, request encoding/size, allowlist behavior, and log contract. Later endpoints are explicitly unimplemented.
