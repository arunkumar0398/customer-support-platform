## Contract and changes

- Added `PATCH /api/tickets/{ticketId}` behind session, CSRF/origin checks, and active membership context.
- ADMIN/AGENT can edit title/description, status, and priority. CUSTOMER can edit only title/description on their own OPEN ticket. Unknown/client-controlled fields are rejected by strict role-specific schemas.
- Allowed status changes: OPEN→IN_PROGRESS, OPEN→RESOLVED, IN_PROGRESS→RESOLVED, RESOLVED→IN_PROGRESS, RESOLVED→CLOSED; CLOSED is final. Reopening RESOLVED requires a 1–500 character `reopenReason`, recorded on the status event.
- Mutations lock the organization row and reload the current active actor membership before authorization; ticket visibility/ownership is included in the scoped DB query. Ticket changes and per-field activity events commit in one transaction. The version increments once per meaningful PATCH; no-op updates emit no event. TK-20 will add expected-version optimistic conflicts.
- Updated API docs with request fields, lifecycle/error behavior, events, and current concurrency limit.
